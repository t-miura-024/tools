# 差分レビュー

ブランチ差分やコミットされていない差分を、マクロ・ミクロの 2 段階でレビューし、結果を difit の comment import スキーマに直接変換して表示する。レビュー結果を Markdown のレポートとして出力したり、レビュー中に自動修正ループを実行したりしない。

## 🧠 前提知識

- レビュー観点・コメント分類: [code-review-criteria.md](code-review-criteria.md) を参照
- 設計語彙: [../_shared/codebase-design-vocabulary.md](../_shared/codebase-design-vocabulary.md) を参照
- 差分取得スクリプト: `~/.cursor/skills/_shared/get-branch-diff.ts`（ブランチ差分）、`~/.cursor/skills/_shared/get-git-diff.ts`（未コミット差分）
- 変更ファイル 6 件以上は SubAgent 並列実行に切り替える
- レビュー前に背景（目的・制約・意図）を抽出する。抽出元はセッション文脈を基本とし、ブランチ差分レビュー時は既存 PR があればその内容も参照する。不十分な場合はユーザーに確認または提供を依頼する
- 可能なら元 Issue / PRD / spec を特定し、仕様適合を Standards と分けて見る

## 🧾 difit comment import 出力

レビュー結果の最終成果物は、次の import スキーマに従う JSON 配列とする。JSON のコードフェンス、Markdown の総合レポート、別テンプレートは出力しない。

```json
[
  {
    "type": "thread",
    "filePath": "src/example.ts",
    "position": { "side": "new", "line": 42 },
    "body": "[question] 🚨 Critical: この分岐では..."
  },
  {
    "type": "thread",
    "filePath": "src/example.ts",
    "body": "[question] 🌍 マクロ: ファイル全体の責務について..."
  },
  {
    "type": "thread",
    "filePath": "src/example.ts",
    "body": "[context] この変更により..."
  }
]
```

各要素には以下を指定する：

- `type`: 常に `"thread"`
- `filePath`: リポジトリルートからの相対パス
- `position`: コード上の特定箇所を指すミクロコメントでは必須。`{"side":"new","line": 行番号}` とする
- `body`: taxonomy プレフィックスで始める本文。内容、重大度、観点、確認手順、修正案など必要な情報は本文内に記載する

ファイル全体に対するマクロコメントは `filePath` のみを指定し、`position` キー自体を省略する。複数ファイルにまたがる指摘は、最も関係の深いファイルにファイルレベルコメントを付けるか、必要に応じて各ファイルに同じ判断を紐づける。`position: null` やダミーの行番号でファイルレベルコメントを表現しない。

### taxonomy

taxonomy の意味を守り、本文の先頭に次のいずれかを付ける：

- `[question]`: AI が人間に判断・対応を求める指摘、確認事項、修正提案。旧来の「指摘」「提案」を含め、アクションが必要なレビューコメントはすべてこれに分類する
- `[context]`: 人間向けの解説、背景、判断根拠、または非アクショナブルな良い点。対応を要求しない情報だけに使う

`[context]` で問題点や修正要求を隠さない。指摘を出す場合は必ず `[question]` にする。レビューコメントがない場合は空配列 `[]` を出力する。

## 🏃 ステップ

`TodoWrite` ツールを使って以下の TODO リストを作成し、進捗を管理する：

1. レビュー対象のヒアリング
2. 背景の抽出・確認
3. 差分の取得
4. 変更規模の判定
5. レビュー実施
6. difit コメントの生成・表示
7. 人間の確認後に review session を終了

### ステップ1: レビュー対象のヒアリング

レビュー開始前に、本文でレビュー対象の選択肢を番号付きで提示し、ユーザーのテキスト回答から対象を判断する。

> レビュー対象を選択してください。

選択肢:

- a) ブランチ差分のみ（ベースブランチとの差分）
- b) コミットされていない差分のみ（ステージ済みのみ）
- c) コミットされていない差分のみ（すべて: ステージ済み + 未ステージ）
- d) ブランチ差分 + コミットされていない差分（ステージ済みのみ）
- e) ブランチ差分 + コミットされていない差分（すべて: ステージ済み + 未ステージ）

### ステップ2: 背景の抽出・確認

差分を読む前に、レビュー判断に必要な背景（目的・制約・意図）を確定する。特定の Vault パス・Skill 名・ファイルパスへの自動探索は必須としない。

#### 抽出元

| 優先 | 抽出元 | 条件 |
| ---- | ------ | ---- |
| 1 | セッション文脈 | 常に実施（会話・ユーザーの説明・既に共有された文脈） |
| 2 | 既存 PR | ステップ 1 で **a / d / e**（ブランチ差分を含む）を選択した場合 |
| 3 | ユーザー指定 | ファイルパスや wikilink を明示された場合のみ `Read` 等で追加 |

#### 手順

1. **セッションから抽出**: セッション文脈をもとに、レビューに必要な背景を短い要約（3〜7 行程度）にまとめる
2. **既存 PR の確認**（ブランチ差分レビューの場合のみ）:
   - 現在ブランチを取得する: `git branch --show-current`
   - 既存 PR の有無を `gh pr list --head "$(git branch --show-current)" --json number,title,body,url --limit 1` で確認する
   - 1 件以上ヒットした場合、`title`・`body`（概要・背景・目的などのセクション）から目的・制約・意図を抽出し、セッション要約と統合する
   - PR が存在しない、または `gh` が利用できない場合はセッション要約のみで続行する（エラーでレビューを止めない）
3. **十分性の判断**: 統合後の要約だけで「なぜこの変更か」「何を達成すべきか」をマクロレビュー（[code-review-criteria.md](code-review-criteria.md) の「背景目的との整合性」）に使えるか判断する
4. **不足時の確認**: 十分でない場合、本文で抽出した背景要約を示して理解を確認するか、背景情報（目的・制約・意図）の提供を依頼する
5. **確定**: ユーザー確認または提供を経て、レビューに採用する背景要約を確定する。PR から採用した場合は要約に PR URL を含める

### ステップ3: 差分の取得

ステップ 1 のヒアリング結果に応じて差分を取得する。

#### ブランチ差分を取得する場合

対象リポジトリ内で `bun run ~/.cursor/skills/_shared/get-branch-diff.ts` を実行して、ベースブランチの検出から各ファイルの詳細 diff 取得までを行う。

出力 JSON から以下を取得する:

- `baseBranch` / `mergeBase`: ベースブランチ名とマージベースコミット
- `files`: 差分ファイル一覧（name-status）
- `stat`: 変更統計
- 各ファイルの詳細 diff（raw diff）

`hasChanges: false` の場合は「差分がありません」と報告して終了する。

#### コミットされていない差分を取得する場合

対象リポジトリ内で `bun run ~/.cursor/skills/_shared/get-git-diff.ts` を実行する。

出力 JSON は変更状態ごとに分離されている:

- `staged`: ステージ済み
- `unstaged`: 未ステージ（追跡済みファイルの未ステージ変更）
- `untracked`: 未追跡

ヒアリングで選択されたスコープに応じて、レビュー対象とする JSON のフィールドを決定する:

- スコープ: ステージ済みのみ → `staged` をレビュー対象とする
- スコープ: すべて（ステージ済み + 未ステージ）→ `staged` + `unstaged` をレビュー対象とする

未追跡ファイルの内容は `untracked` の情報（ファイルパス等）をもとに `Read` ツールで直接読み取る。

`hasChanges: false` の場合は「差分がありません」と報告して終了する。

#### 両方取得する場合

ブランチ差分とコミットされていない差分の両方を取得し、レビュー時に統合して扱う。

### ステップ4: 変更規模の判定

変更ファイル数に応じて実行方法を決定する。

| 条件   | 判定基準 | 実行方法 |
| ------ | -------- | -------- |
| 小規模 | 変更ファイル 5 件以下 | 単一フローで順次実行 |
| 大規模 | 変更ファイル 6 件以上 | Task ツールで並列実行 |

### ステップ5: レビュー実施

ステップ 2 で確定した背景要約を常に参照する。

#### 小規模変更の場合（順次実行）

1. マクロレビューを実施する。[code-review-criteria.md](code-review-criteria.md) の「背景目的との整合性」と「仕様適合」を必ず確認する
2. ミクロレビューを実施する

#### 大規模変更の場合（Task ツールで並列実行）

以下のサブエージェントを Task ツールで並列起動する。各 Agent の prompt には、ステップ 2 で確定した背景要約を必ず含める。

##### Agent 1: マクロレビュー

- アーキテクチャ観点のレビュー（「背景目的との整合性」と「仕様適合」を必ず確認）
- 横展開候補の検出（コードベースの類似実装を検索）
- ファイル全体に紐づく指摘は `position` を付けずに記録する

##### Agent 2: ミクロレビュー

- コード詳細のレビュー（背景要約を踏まえ、目的に沿った実装かを確認する）
- 特定行への指摘は `position` に新しい側の行番号を記録する

### ステップ6: difit コメントの生成・表示

1. 全レビュー結果を集約し、重複を除く
2. 対応が必要な指摘・確認事項・提案は `[question]`、解説や非アクショナブルな情報は `[context]` に分類する
3. 各コメントを `type`・`filePath`・必要に応じた `position`・`body` を持つ import スキーマの要素に変換する
4. JSON 配列をそのまま stdin に渡して、ベースブランチ名付きで difit を開始する。例：

```bash
mt difit start <base-branch> <<'JSON'
[
  {
    "type": "thread",
    "filePath": "src/example.ts",
    "position": { "side": "new", "line": 42 },
    "body": "[question] ⚠️ Warning: ..."
  },
  {
    "type": "thread",
    "filePath": "src/example.ts",
    "body": "[context] 🌍 マクロ: ..."
  }
]
JSON
```

5. `mt difit start` が出力した URL を案内し、ブラウザ上で人間が各 thread を確認・reply・resolve できる状態にする

JSON 配列が空の場合も `mt difit start <base-branch>` に `[]` を渡す。コメントを Markdown ファイルや独自のレビュー形式に変換しない。

### ステップ7: review session の終了

人間がブラウザでレビューを確認し終えたら、standalone の終了処理として必ず次を実行する：

```bash
mt difit done
```

これはゲートや自動修正ループを開始する処理ではない。`mt-review-diff` standalone は、コメントを表示し、人間の確認を待ち、`mt difit done` で review session を終了して完了する。

## ✅ 完了条件

- レビュー開始前に背景要約が確定している（ステップ 2）
- すべての差分ファイルがマクロ・ミクロの両観点でレビューされている
- レビュー結果が difit comment import スキーマの JSON 配列として直接出力されている
- 特定行へのコメントは `position` を持ち、ファイル全体へのマクロコメントは `position` を省略している
- 指摘・確認事項・提案は `[question]`、解説や非アクショナブルな情報は `[context]` になっている
- 人間の確認後、`mt difit done` で review session が終了している

## 📦 アウトプット

difit に渡す comment import スキーマの JSON 配列。各コメントには次を含める：

- `type: "thread"`
- `filePath`: リポジトリルートからの相対パス
- 特定行へのコメントの場合のみ `position: { side: "new", line: number }`
- taxonomy プレフィックス（指摘は `[question]`、解説は `[context]`）を先頭に持つ `body`

レビュー終了時の終了コマンドは `mt difit done` とする。

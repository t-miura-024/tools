# Skillの仕組み（skill mechanics）

skill固有の分岐であり、[`writing-for-agents`](SKILL.md) の一部である。文書がskillである場合に変わる点（frontmatter、呼び出し（invocation）の選択、ルータースキル）を扱う。それ以外の書き方は `SKILL.md` の汎用リファレンスがすべてである。

## 呼び出し（invocation）

二つの選択肢であり、二つの負荷の交換である。

- **モデル呼び出し型（model-invoked）**のskillは `description` を保持し、エージェントが自律的に発火でき、他のskillから到達できる。名前の直接入力も依然可能である。モデル呼び出しは常にユーザーの到達を*含み*、descriptionはエージェントの発見を追加するだけで人間の到達を奪わない。descriptionはskillの最上位の文脈ポインタであり、常時読み込みを強いられる。発見可能性と引き換えの永続的な文脈負荷である。内容がすべてリファレンスのモデル呼び出し型skillは、共有リファレンスの置き場所にもなる。他のskillが呼び出せるため、複数のskillが必要とするリファレンスを一箇所に置ける。仕組みは、`disable-model-invocation` を省略し、触发分岐を担うモデル向けdescriptionを書くことである（`SKILL.md` のポインタ記述規則が全面的に適用される）。
- **ユーザー呼び出し型（user-invoked）**のskillはエージェントの到達からdescriptionを外す。名前を直接入力する人間のみが呼び出せ、他のskillからは到達できない。文脈負荷はゼロだが、認知負荷を消費する。存在を覚える索引が人間自身になる。仕組みは、`disable-model-invocation: true` を設定することであり、`description` は人間向けになる。一行の要約であり、触发一覧は外す。

エージェントが自力でskillに到達しなければならない場合、あるいは他のskillが到達しなければならない場合にのみモデル呼び出しを選ぶこと。手でのみ発火するならユーザー呼び出しにし、文脈負荷を払わないこと。

二つのユーザー呼び出し型skillが共に必要とする共有リファレンスは、どちらにも置けない。descriptionがなければ互いに発火できないからである。skill機構の外の素のファイルに押し出すこと。あらゆるskillが指せる外部参照である。

## 呼び出しによる分割（splitting by invocation）

分割の呼び出し切り分けである（手順の切り分けは `SKILL.md` にある）。自律触发すべき個別の先行語がある場合（プロンプトで実際に使う触发語）、あるいは他のskillが到達しなければならない場合に、モデル呼び出し型skillを切り分けること。常時読み込まれるdescriptionが増えて文脈負荷を払うため、その独立到達に見合う必要がある。

## ルータースキル（router skills）

ユーザー呼び出し型skillが覚えきれない数に増えた場合、その積み上がった認知負荷は**ルータースキル**で治す。他の skill 群とそれぞれに手を伸ばすべきときを名指しする一つのユーザー呼び出し型skillであり、人間が覚える skill を多数から一つにする。示唆のみでき、発火はできない。ユーザー呼び出し型skillにdescriptionはなく、人間以外は到達できないからである。

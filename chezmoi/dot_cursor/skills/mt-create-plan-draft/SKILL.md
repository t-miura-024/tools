# mt-create-plan-draft

セッションの内容を入力として受け取り、非対話モードの `mt plan draft` CLI を呼び出して、GitHub に draft 計画 Issue を起票する。tado ワークフローは使わず、この SKILL.md の指示のみで完結する。

## 🧭 棲み分け

- **mt-create-plan**: 計画を新規作成・リファインメントする。tado ワークフローを使い、plan-format.md テンプレートに従って対話的に計画を練る。
- **mt-create-plan-draft（本スキル）**: セッションの内容をそのまま draft として起票する。テンプレートには従わず、セッション内容の忠実な記録を優先する。

## 🧠 前提知識

- 非対話モードの CLI: `mt plan draft --title <title> --body-file <path> --repo <local-path>`
    - 3 引数は「すべて揃う or すべて無い」の二択。一部だけ指定するとエラー（stderr + 非ゼロ exit）になる。本スキルでは必ず 3 つとも指定する。
    - `--repo` はローカルパスを受け取る（`owner/repo` 形式ではない）。CLI 内部が `git remote get-url origin` から owner/name を解決する。
    - `--body-file` は draft 本文を格納したファイルへのパス。本文は一時ファイルに書き出して渡す（シェルエスケープ回避）。
    - 引数なしで実行すると従来通り TUI が起動する。本スキルでは絶対に引数なしで呼び出さない。
- 成功時は stdout に JSON（`number`, `title`, `url`, `repo` の 4 フィールド）を出力する。
- エラー時は stderr にメッセージ + 非ゼロ exit code。

## 🏃 ステップ

1. セッション内容とタイトルを確定する。
    - 入力として渡されたセッション内容（または現在のセッションの経緯）を読み込む。
    - draft のタイトルを、計画を一言で表す簡潔な名前に決める。
    - 起票先リポジトリのローカルパスを確定する。ユーザーから指定がなければ、現在の作業ディレクトリ（セッションが行われているリポジトリ）のパスを使う。

2. draft 本文を組み立て、一時ファイルに書き出す。
    - 本文はセッション内容の忠実な記録とする。plan-format.md テンプレートには従わなくてよい。
    - 過不足なく盛り込む（下記「本文に含める内容」参照）。
    - 読みやすい Markdown で記述する。
    - `mktemp` で生成した一時ファイル（または `/tmp/mt-plan-draft-body.md` など）に書き出す。

3. CLI を呼び出して draft Issue を作成する。

    ```bash
    mt plan draft --title "<タイトル>" --body-file "<一時ファイルパス>" --repo "<ローカルパス>"
    ```

    - 3 引数は必ず同時に指定する。
    - パスやタイトルに空白・特殊文字が含まれる場合は引用符で囲む。

4. 結果を処理する。
    - 成功（exit 0）: stdout の JSON を解析し、`number`, `title`, `url`, `repo` をユーザーに報告する。
    - 失敗（非ゼロ exit）: stderr のメッセージをユーザーに伝え、原因（body ファイルが見つからない、gh 未認証、リポジトリ解決失敗など）に応じた次の対応を案内する。

5. 一時ファイルを削除する。

### 本文に含める内容

セッションの内容を過不足なく記録する。以下を目安にしつつ、セッションで実際に得られた内容を漏らさず、かつ無関係な水増しはしない。

- 背景・目的: なぜこの計画を立てるに至ったか、解決したい課題
- セッションで確定した方針・決定事項
- 計画の実体: やること（タスク・ステップ）、アプローチ、スコープ
- 未解決事項・懸念点・保留中の判断（あれば）
- 関連するコンテキスト（参照したファイル、前提知識、制約など）

## ✅ 完了条件

- `mt plan draft` が非対話モード（3 引数指定）で呼び出され、draft 計画 Issue が作成されている
- draft 本文にセッションの内容が過不足なく盛り込まれている
- 成功時の JSON 出力（number, title, url, repo）がユーザーに報告されている
- 一時ファイルが削除されている

## 📦 アウトプット

- 作成された draft Issue の番号・タイトル・URL・リポジトリ（JSON の 4 フィールド）

## ⚠️ 注意事項

- 引数を一部だけ指定するとエラーになる。`--title`, `--body-file`, `--repo` は必ず 3 つ同時に指定する。
- `--repo` に `owner/repo` 形式を渡さない。必ずローカルパスを渡す。
- 引数なしで実行すると TUI が起動するため、本スキルでは絶対に引数なしで呼び出さない。
- 本文は一時ファイル経由で渡す（`--body` 直接指定は使わない）。
